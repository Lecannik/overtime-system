# Комплексное обновление OvertimePro: фильтры, дашборд, аналитика, мобильная адаптация, админ-функции и багфиксы

## Контекст
Пользователь запросил ряд улучшений, затрагивающих страницы «Главная» (DashboardPage), «Согласование» (ReviewPage) и «Аналитика» (AnalyticsPage), а также общую мобильную адаптацию системы для удобной подачи заявок с телефона.
Дополнительно требуется предоставить администраторам возможность редактировать даты/проекты/описание в одобренных и отклонённых заявках сотрудников (с жёстким аудитом), исправить баги календаря плоских дат Flatpickr, реструктурировать дашборд администратора (заменив бесполезные личные показатели на глобальные) и оценить сложность создания формы «Отгулов» (списания накопленных часов).

### Блок 2. Реструктуризация Главной страницы для Администраторов и Руководителей

**Проблема:** Сейчас администраторы на главной странице видят все заявки кучей, без структуры. Личные карточки (дашборд-показатели) показывают нули (т.к. у админа нет личных переработок), что бесполезно.

**Решение:** 
Разделить страницу `DashboardPage` для ролей `admin` (и опционально `manager`/`head`) на две вкладки (табы):
1. **Вкладка «Мои переработки»** (по умолчанию):
   - Показывает личные карточки (личные часы за тек./прошлый месяц).
   - Показывает таблицу только личных заявок администратора (фильтр по `user_id == current_user.id` на бэкенде).
2. **Вкладка «Все сотрудники»** (или «Обзор компании»):
   - Показывает **глобальные показатели компании** (загружаются из эндпоинта `/analytics/summary`):
     - «Одобрено часов по компании (в тек. месяце)»
     - «Одобрено часов по компании (в прошлом месяце)»
     - «Всего заявок в системе»
     - «Заявок на согласовании» (количество PENDING)
   - Показывает таблицу всех заявок сотрудников с фильтрами по отделам, проектам, статусу и датам.

> [!NOTE]
> Это решает проблему неструктурированности данных и заменяет бесполезные личные "нули" администратора на важные показатели компании.

### Блок 9. Баг Flatpickr — смещение даты и неприменение времени

**Проблема:** При создании заявки дата смещается на 1 день назад. Введённое время не применяется, пока не нажмёшь Enter.

**Решение:**

#### [MODIFY] [CreateOvertimeModal.tsx](file:///home/nik/Dev/overtime-prod/frontend/src/components/pages/CreateOvertimeModal.tsx)
- **Смещение даты**: Заменить `selectedDates[0].toISOString()` на локальный парсинг `toLocalISOString(selectedDates[0])` в обработчиках `onChange`. Иначе конвертация в UTC сдвигает время назад (UTC+5 для Алматы) и дата уезжает на предыдущий день.
- **Ввод времени**: Добавить обработчик `onClose` в конфигурацию Flatpickr:
  ```ts
  onClose: (selectedDates) => {
      if (selectedDates[0]) {
          setStartTime(toLocalISOString(selectedDates[0]));
      }
  }
  ```
  Это принудительно сохранит в стейт изменения времени при закрытии пикера (без необходимости нажимать Enter).

## Оценка фичи: Оформление отгулов (изъятие часов)

**Цель:** Позволить сотрудникам списывать накопленные согласованные часы переработок в качестве отгулов.

**Сложность:** Средняя (требуется около 1.5 - 2 часов чистой разработки).

**План реализации (если утверждается):**

1. **База данных (БД)**:
   - Новая модель `TimeOff` (`id`, `user_id`, `date`, `hours`, `description`, `status: PENDING/APPROVED/REJECTED/CANCELLED`, `created_at`).
2. **Бэкенд логика**:
   - Вычисление баланса: `баланс = (сумма approved_hours по APPROVED переработкам) - (сумма hours по APPROVED отгулам)`.
   - Эндпоинты:
     - `POST /time-offs/` — создание заявки на отгул. Валидация: количество запрашиваемых часов не должно превышать текущий баланс сотрудника.
     - `GET /time-offs/` — список отгулов сотрудника.
     - `GET /time-offs/pending` — список отгулов для согласования руководителями.
     - `POST /time-offs/{id}/review` — согласование отгула руководителем.
     - `POST /time-offs/{id}/cancel` — отмена отгула.
3. **Фронтенд**:
   - На Главной странице вывести плашку «Доступно для отгула: X часов».
   - Кнопка «Запросить отгул» (открывает модалку с формой).
   - Новая вкладка на главной «Мои отгулы» (таблица со статусами).
   - Секция согласования отгулов для руководителей на странице «Согласование» (ReviewPage).
